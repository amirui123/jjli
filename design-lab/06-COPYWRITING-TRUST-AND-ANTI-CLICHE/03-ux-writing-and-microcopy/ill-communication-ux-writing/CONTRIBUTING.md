Contributing

Thanks for wanting to make ill-communication better. This is a small, opinionated skill, so contributions that fit the spirit are very welcome.

The kinds of contributions that help most

New AI-writing tells. Spotted a pattern the skill misses? Open an issue with a real before/after example: the slop version and the human version. Concrete examples beat descriptions every time, and they go straight into references/ai-tells.md.

New microcopy patterns. Button, error, empty state, or accessibility guidance that belongs in references/microcopy.md. Same rule: show it with an example.

Fixes. Typos, broken links, a rule that contradicts another rule, a replacement suggestion that reads badly. All fair game.

Voice profile translations. The voice profile template is in English. If you want to adapt it for another language or locale, that helps people writing in those languages.

How to propose a change

The easy way: open an issue describing what you'd add or fix, with an example. Good for ideas and discussion.

The direct way: open a pull request editing the relevant file. Good for fixes and small additions you're confident about. Keep PRs focused on one thing.

If you're not sure which, open an issue first and we'll work it out.

The one hard rule

No em dashes. Anywhere. In your contribution, in your examples, in your PR description. This skill exists partly to kill them, so a contribution containing one will be sent back with affection. En dashes in ranges (2019–2024) are fine. Hyphens in compounds (opt-in) are fine.

Style

Match what's already there: plain, direct, British English, sentence case headings, examples over adjectives. If you're adding to a reference file, read the surrounding entries first and follow the format.

Tone

Be kind. The point of this skill is communication that respects the reader, so let's hold the same standard with each other.
